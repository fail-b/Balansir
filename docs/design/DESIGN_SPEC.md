## 3. Навигация и таб-бар
**3 вкладки: Главная · Статистика · Счета** + кнопка «+». Настройки — не вкладка, а экран по шестерёнке.
Почему 3: отдельный экран «Операции» дублировал ленту Главной. Лента и поиск живут на Главной; когда появятся бюджеты/цели (§5), вопрос о 4-й вкладке решается заново.

Реализация (уже сделана, `App/ContentView.swift`) — **нативный `TabView` iOS 26**, свой бар не рисовать:
- `.tabBarMinimizeBehavior(.onScrollDown)` — при скролле вниз бар сворачивается до активной вкладки;
- сводка рядом со свёрнутым баром — `.tabViewBottomAccessory(isEnabled: isScrolled)` (`Views/Components/TabBarSummary.swift`), показывается только когда экран прокручен ниже 30 pt (`reportsScroll`);
- «+» — вкладка `AppTab.add` с `role: .search` (система рисует её отдельным стеклянным кругом справа); тап перехватывается в `tabSelection` и открывает шит новой операции с любой вкладки. Вкладка `.search` занята под «+», поэтому **поиск в таб-бар не переносить** — он живёт в шапке Главной (§4.1.4).
- Активная вкладка: иконка и подпись `accent` (через `.tint`).

Содержимое сводки:
- Главная: «Сегодня −3 320 ₽» + справа «Октябрь −84 320 ₽» (`ink2`). **В режиме поиска** с непустым запросом: «Найдено 12» + справа сумма расходов среди найденного «−8 400 ₽».
- Статистика: «Октябрь 84 320 ₽» + «В день 10 540 ₽».
- Счета: «Всего на счетах 286 420 ₽».

3. **Карусель счетов** (горизонтальный скролл, фильтр ленты) — см. §4.1.3.
4. **Лента операций по дням:** заголовок «Сегодня / Вчера / 6 октября» + справа сумма **только расходов** дня (`−3 320 ₽`); операции дня — в одной карточке (радиус 22), строки через `EntryRow`. Лента бесконечная (вся история), `LazyVStack` внутри `ScrollView`, чтобы не строить все строки сразу.

#### 4.1.4 Поиск на Главной (новое)
Ориентир — системный жест iOS «потянуть вниз → поиск» (Spotlight на домашнем экране, поиск в Почте/Заметках) + морфинг Liquid Glass iOS 26.

**Состояния:**
```
1. Обычное                 2. Тянем вниз (0…70 pt)        3. Поиск активен
Октябрь ⌄      (🔍 ⚙)      Окт…  (🔍━━━━━━━━━ )           (🔍 Категория, счёт… ⓧ) (✕)
[hero]                      [hero]                          [карусель счетов]
[карусель]                  …                               [результаты по дням]
[лента]                                                     ─── клавиатура ───
```
**Вход в поиск — два пути, итог одинаковый:**
- **Тап по лупе** в шапке.
- **Жест «потянуть вниз»** у верха ленты (оверскролл, только когда поиск не активен):
  - прогресс `p = clamp(оверскролл / 70 pt, 0…1)`;
  - пока тянем: стеклянная капсула лупы растягивается влево (ширина от 44 до полной ширины шапки пропорционально `p`), «Октябрь ⌄» и шестерёнка плавно гаснут (opacity `1 − p`);
  - при `p` = 1: лёгкий хаптик (`.sensoryFeedback(.impact(weight: .medium))`, один раз за жест) и лупа чуть «подпрыгивает» (scale 1.1) — сигнал «отпусти, будет поиск»;
  - отпустили при `p` = 1 → активация; отпустили раньше → пружиной обратно в обычное состояние.

**Активация** (spring ~0.35 с, damping 0.8): лупа морфится в строку поиска (`glassEffectID` в общем `GlassEffectContainer`), строка встаёт на место шапки; справа от неё — круглая стеклянная кнопка ✕ 44 pt; **поле сразу получает фокус — появляется клавиатура** (как в Spotlight: потянул — и сразу печатаешь). Hero-карточка уезжает вверх и гаснет (`.move(edge: .top)` + `.opacity`); карусель счетов остаётся и работает как дополнительный фильтр.

**Строка поиска:** высота 44, стекло, капсула; слева `magnifyingglass` `ink2`; поле 17, плейсхолдер «Категория, счёт или заметка»; при непустом запросе справа — `xmark.circle.fill` `ink2` (очистить, фокус остаётся). Клавиатура: `.submitLabel(.search)`, автокоррекция выключена, автокапитализация выключена.

**Результаты:** фильтрация по мере ввода, без кнопки «Найти». Та же лента по дням (суммы дней — по найденным расходам). Пустой запрос — полная лента. Ничего не найдено — по центру «Ничего не найдено» (17 semibold `ink`) + «Попробуйте другое слово» (13 `ink2`). Сводка в свёрнутом таб-баре — §3.

**Правила поиска** (в `HomeViewModel`, покрыть тестами):
- запрос обрезается по краям; регистр не важен; **«ё» = «е»** (`folding(options: [.caseInsensitive, .diacriticInsensitive], locale: ru_RU)` либо явная замена);
- ищем по: названию категории, названию счёта (у перевода — по обоим счетам), заметке;
- если запрос — число (цифры, пробелы, запятая), дополнительно ищем по сумме: «2400», «2 400» и «2400,5» находят операцию на 2 400,50 ₽ (сравнение по префиксу строки суммы без разделителей);
- поиск идёт по всей истории и сочетается с выбранным счётом в карусели (И).

**Выход из поиска:**
- ✕ рядом со строкой → запрос очищается, фокус снимается, всё пружиной возвращается в обычное состояние;
- свайп по ленте вниз прячет клавиатуру (`.scrollDismissesKeyboard(.immediately)`); если запрос **пустой** и фокуса нет — поиск закрывается сам; если запрос есть — режим поиска остаётся (поле без фокуса, тап по нему возвращает клавиатуру);
- открытие шита «+» или редактирования операции режим поиска не сбрасывает; после сохранения результаты пересчитываются.

**Доступность:** Reduce Motion (`accessibilityReduceMotion`) → без растягивания по жесту и без «подпрыгивания», переход — простой crossfade. VoiceOver: основной путь — кнопка «Поиск»; жест — дополнительный.

**Реализация (подсказки):** состояние жеста — во View (`@State pullProgress`, `@FocusState isSearchFocused`); запрос и режим — в VM (`searchQuery`, `isSearchActive`). Оверскролл: `onScrollGeometryChange(for: CGFloat.self) { max(0, -($0.contentOffset.y + $0.contentInsets.top)) }`. Момент «отпустил»: `onScrollPhaseChange` — переход из `.interacting`. Модификатор для оверскролла положить рядом с `reportsScroll` в `Views/Components/ScrollOffsetReporter.swift`. Шапку и её состояния вынести в отдельный компонент `Views/Home/HomeHeader.swift`, чтобы `HomeView` не разрастался. Числа (70 pt, 44 pt, 1.1) — константами в `Theme`.
